# Справочник API DV Auth

Все тела запросов и ответов это JSON (UTF-8). Тело POST-запроса не больше 16 КБ, обязателен
заголовок `Content-Type: application/json`. Все ответы идут с `Cache-Control: no-store`.

## Два порта

- **Внутренний** (по умолчанию 3011): для ваших приложений. Каждый запрос с заголовком
  `Authorization: Bearer <секрет приложения>`. Все адреса ниже, кроме раздела «Публичный порт».
- **Публичный** (по умолчанию 3010): для приложения чата. Секрет не нужен.

## Ошибки

Ответ с ошибкой: статус HTTP и тело `{"error": "<код>", "message": "<текст для человека>"}`.

- 400 `bad_request`: неверные поля запроса; `invalid_code`: код не подошёл при включении TOTP.
- 401 `unauthorized`: неверный секрет приложения; `invalid_code`: неверный код; `ticket_expired`:
  талон истёк или сгорел; `invalid_number`: неверное число в чате; `not_verified`: чат не
  подтвердил личность.
- 403 `wrong_account`: подтверждает чужой аккаунт чата.
- 404 `not_found`: нет такого адреса, запроса или запрос устарел.
- 409 `conflict`: действие невозможно в текущем состоянии (TOTP уже включён, аккаунт чата уже
  привязан другому человеку).
- 413 и 415: тело слишком большое или не JSON.
- 429 `locked`: слишком много неудач, подождите 15 минут.
- 503 `unavailable`: способ не настроен (нет ключа TOTP или адреса Synapse) или чат недоступен.
- 500 `internal`: внутренняя ошибка, подробности в журнале сервиса.

`message` можно показывать людям, кроме `unauthorized` (это ошибка настройки приложения).

## Общие поля

- `subject`: строка от 1 до 128 символов, идентификатор человека в вашем приложении.
- `ip`: адрес человека, строка до 64 символов. Если не передан, учитывается как `unknown`
  (тогда блокировка по адресу не работает, всегда передавайте).
- `agent`: название браузера (заголовок User-Agent), до 500 символов, показывается человеку в чате.

## Состояние человека

`GET /v1/status?subject=...`

    {
      "enabled": true,           // включён ли хоть один способ
      "chatAvailable": true,     // настроен ли чат на сервере
      "chatLinked": true,        // привязан ли чат у человека
      "matrixId": "@anna:example.org",
      "totpAvailable": true,     // настроен ли TOTP на сервере
      "totpEnabled": false,
      "recoveryLeft": 10,        // сколько запасных кодов не использовано
      "methods": ["chat", "recovery"]   // чем человек может подтвердить вход сейчас
    }

`GET /v1/subjects`: список `{"subjects": ["42", ...]}` всех людей приложения с включённым вторым
фактором (для списка в админке).

## Вход

`POST /v1/login/begin`  `{"subject", "ip"}`

Ответ `{"required": false}`, если второго фактора нет, иначе
`{"required": true, "ticket": "...", "methods": [...]}`. Может ответить 429, если по человеку
или адресу слишком много неудач.

`POST /v1/login/code`  `{"ticket", "code", "ip"}`

`code`: шесть цифр TOTP или запасной код (регистр и дефисы не важны). Успех: `{"ok": true,
"subject": "..."}`. Талон сгорает. Неудача: 401, талон теряет одну попытку из пяти.

`POST /v1/login/chat/start`  `{"ticket", "ip", "agent"}`

Ответ `{"challenge", "number", "qr", "expiresIn"}`. `number`: трёхзначное число для показа
крупно. `qr`: строка вида `dvchat://auth#...`, из неё рисуется QR-код. Прежний запрос этого
человека гасится. 400, если чат у человека не привязан.

`POST /v1/login/chat/status`  `{"ticket"}`

Ответ `{"state": "pending"|"approved"|"failed"|"none", "subject"?}`. `approved` выдаётся один раз:
после него талон сгорает. `failed`: запрос отменён (три неверных числа, чужой аккаунт чата) или
время вышло.

`POST /v1/check`  `{"subject", "code", "ip"}`

Проверка кода (TOTP или запасного) для чувствительных действий в приложении. Ответ
`{"ok": true}` или 401. Неудачи считаются в блокировку, запасной код при успехе сгорает.

## Коды из приложения (TOTP)

`POST /v1/totp/begin`  `{"subject", "label"?}`

Ответ `{"secret": "<base32>", "uri": "otpauth://totp/..."}`. Покажите QR-код из `uri` и ключ
`secret` для ввода руками. Пока `enable` не вызван, способ не считается включённым. Повторный
вызов выдаёт новый секрет. 409, если TOTP уже включён. 503, если нет DVAUTH_TOTP_KEY.

`POST /v1/totp/enable`  `{"subject", "code"}`

Проверяет первый код. Ответ `{"recoveryCodes": ["XXXX-XXXX-XXXX", ...] | null}`: запасные коды
выдаются, только если их у человека ещё не было, и показываются один раз.

`POST /v1/totp/disable`  `{"subject"}`

Выключает TOTP. Если не остаётся ни одного способа, запасные коды удаляются.

## Запасные коды

`POST /v1/recovery/new`  `{"subject"}`

Выпускает десять новых кодов, старые перестают работать. Ответ `{"recoveryCodes": [...]}`.
409, если у человека нет ни одного способа.

## Чат

`POST /v1/chat/link/start`  `{"subject", "ip", "agent"}`

Начинает привязку. Ответ как у `login/chat/start`.

`POST /v1/chat/link/status`  `{"subject"}`

Ответ `{"state": ..., "matrixId"?, "recoveryCodes"?}`. На `approved` привязка записана, а при
первом включении фактора приходят запасные коды (один раз). 409, если этот аккаунт чата уже
привязан другому человеку того же приложения.

`POST /v1/chat/unlink`  `{"subject"}`

Отвязывает чат. Если не остаётся способов, запасные коды удаляются.

## Сброс

`POST /v1/reset`  `{"subject"}`

Снимает всё: TOTP, запасные коды, привязку чата, талоны и запросы. Вызывайте только по решению
администратора, когда человек потерял и телефон, и запасные коды. Закрыть сессии человека в вашем
приложении нужно самим.

## Публичный порт

`GET /health`: `{"status": "ok", "service": "dvauth"}`.

`GET /v1/chat/info?challenge=...`

Для экрана подтверждения в приложении чата: `{"title": "DV Cloud", "purpose": "login"|"link",
"ip": "203.0.113.7", "agent": "..."}`. 404, если запрос не найден или устарел.

`POST /v1/chat/confirm`  `{"challenge", "number", "openid"}`

Подтверждение из приложения чата. `number`: число с экрана, `openid`: одноразовый токен OpenID
из Matrix. Ответ `{"ok": true, "purpose": "login"|"link"}`. Три неверных числа отменяют запрос,
подтверждение чужим аккаунтом тоже (403). Блокировка по адресу: тридцать неудач за 15 минут.
Подробнее: docs/CHAT.md.
