# Как подключить своё приложение к DV Auth

Здесь схема и примеры. Полный справочник запросов: docs/API.md.

## Что нужно от приложения

1. Хранить адрес внутреннего порта DV Auth и свой секрет (из DVAUTH_CLIENTS) в настройках.
2. Идентифицировать людей стабильным номером (`subject`), а не логином.
3. Передавать в DV Auth настоящий адрес человека (`ip`): по нему считается блокировка перебора и
   он показывается человеку в приложении чата.
4. Сессию после пароля открывать только когда второй шаг пройден.
5. Отказывать во входе (а не пропускать), если DV Auth недоступен: «не знаю, включён ли второй
   фактор» нельзя считать «не включён».

Каждый запрос идёт с заголовком `Authorization: Bearer <секрет приложения>` и, для POST, с
`Content-Type: application/json`.

## Вход в два шага

**Шаг 1.** Приложение проверило логин и пароль. Теперь:

    POST /v1/login/begin
    {"subject": "42", "ip": "203.0.113.7"}

Ответ, если второго фактора у человека нет:

    {"required": false}

Открывайте сессию как обычно. Ответ, если есть:

    {"required": true, "ticket": "...", "methods": ["chat", "totp", "recovery"]}

Сессию не открывайте. Отдайте браузеру талон и список способов.

**Шаг 2а. Код.** Человек ввёл шесть цифр из приложения-аутентификатора или запасной код:

    POST /v1/login/code
    {"ticket": "...", "code": "123456", "ip": "203.0.113.7"}

Ответ при успехе: `{"ok": true, "subject": "42"}`. Теперь открывайте сессию для этого человека.
При ошибке ответ 401 с кодом `invalid_code`, 429 при блокировке, 401 с `ticket_expired`, когда
талон кончился или сгорел.

**Шаг 2б. Чат.** Приложение запрашивает QR и число:

    POST /v1/login/chat/start
    {"ticket": "...", "ip": "203.0.113.7", "agent": "Mozilla/5.0 ..."}

Ответ: `{"challenge": "...", "number": "472", "qr": "dvchat://auth#...", "expiresIn": 180}`.
Покажите человеку QR-код из строки `qr` и число `number` крупно. Страница опрашивает приложение,
а приложение раз в две секунды опрашивает DV Auth:

    POST /v1/login/chat/status
    {"ticket": "..."}

Состояния: `pending` (ждём), `approved` (подтверждено, в ответе `subject`), `failed` (отменено или
время вышло), `none` (запрос ещё не создавался). На `approved` открывайте сессию.

QR для телефона лучше дополнить ссылкой: тот же текст `qr` можно открыть кнопкой «Открыть в чате»,
это удобно, когда вход идёт с самого телефона.

## Настройки безопасности в приложении

Все эти запросы приложение делает от имени уже вошедшего человека. Перед опасными действиями
проверьте его пароль сами, а если у него включены коды из приложения, проверьте ещё и код
запросом `POST /v1/check`.

- Состояние: `GET /v1/status?subject=42`.
- Включить коды: `POST /v1/totp/begin` (в ответе секрет и ссылка `otpauth://` для QR-кода),
  затем `POST /v1/totp/enable` с первым кодом. В ответе могут быть запасные коды (один раз).
- Выключить коды: `POST /v1/totp/disable`.
- Привязать чат: `POST /v1/chat/link/start`, показать QR и число, опрашивать
  `POST /v1/chat/link/status`. Отвязать: `POST /v1/chat/unlink`.
- Новые запасные коды: `POST /v1/recovery/new`.
- Сброс (потерян телефон и коды): `POST /v1/reset`, только по решению администратора.

Запасные коды сервис показывает один раз. Покажите их человеку сразу и предложите сохранить.

## Пример на TypeScript

Минимальный клиент (так сделано в DV Cloud):

    async function authCall(method: 'GET' | 'POST', path: string, body?: object) {
      let res: Response;
      try {
        res = await fetch(AUTH_URL + path, {
          method,
          headers: { authorization: `Bearer ${AUTH_SECRET}`, ...(body ? { 'content-type': 'application/json' } : {}) },
          body: body ? JSON.stringify(body) : undefined,
          signal: AbortSignal.timeout(8000),
        });
      } catch {
        throw new HttpException('Сервис второго фактора недоступен', 503); // вход закрыт, не открыт
      }
      const json = await res.json().catch(() => ({}));
      if (res.ok) return json;
      if (res.status >= 500 || json.error === 'unauthorized') throw new HttpException('Сервис второго фактора недоступен', 503);
      throw new HttpException(json.message ?? 'Ошибка второго фактора', res.status);
    }

    // после проверки пароля:
    const r = await authCall('POST', '/v1/login/begin', { subject: String(user.id), ip: req.ip });
    if (r.required) return { twoFactor: { ticket: r.ticket, methods: r.methods } };
    // иначе открыть сессию

Неверный секрет приложения даёт `unauthorized`: человеку это показывать не нужно, его вины тут нет.

## Если приложение работает без DV Auth

Сделайте подключение необязательным: пока адрес и секрет не заданы, вход идёт по паролю. Так
сделано в DV Cloud: люди без DV Auth продолжают пользоваться облаком.
