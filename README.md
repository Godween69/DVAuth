# DV Auth

Маленький самостоятельный сервис второго фактора входа. Он не заменяет ваши приложения и не хранит
пароли: приложение проверяет пароль само, а потом спрашивает DV Auth, подтвердил ли человек вход
вторым способом. Один такой сервис может обслуживать сколько угодно ваших сайтов и сервисов.

Написан на Node.js без фреймворков, единственная зависимость это драйвер PostgreSQL. Исходный код
открыт по лицензии AGPL-3.0. Автор: DVB Studio (GitHub: Godween69).

## Зачем он нужен

Пароль защищает вход плохо: его подбирают, крадут, повторяют на разных сайтах. Всё, что торчит в
интернет (облако, почта, админка), стоит закрыть вторым фактором. Писать его заново в каждом
проекте долго и опасно: ошибки в таких вещах стоят дорого. DV Auth делает это один раз, а ваши
приложения подключаются к нему несколькими простыми запросами.

Два способа второго фактора:

- **Подтверждение в чате на Matrix** (основной). При входе сайт показывает QR-код и число.
  Человек сканирует код в приложении чата, видит, кто и откуда входит, вводит число с экрана.
  Так же работают входы в WhatsApp Web и Telegram Web, но на вашем собственном сервере и без
  чужих сервисов. Нужен чат на Matrix и приложение, которое умеет это подтверждение (для DVChat
  оно описано в docs/CHAT.md).
- **Коды из приложения-аутентификатора** (запасной). Любое приложение с TOTP (RFC 6238):
  Google Authenticator, Aegis, 2FAS, FreeOTP. Работает без чата и без интернета на телефоне.

К обоим способам прилагаются **десять одноразовых запасных кодов** на случай потери телефона.

## Чем он хорош

- **Один сервис на все приложения.** Каждое приложение имеет свой секрет и видит только своих людей.
- **Маленький и понятный.** Менее семисот строк кода, зависимость одна. Его можно прочитать за вечер.
- **Не знает ваших паролей.** Приложение само проверяет пароль и сообщает сервису только
  «этот человек (его номер у вас) входит». Утечка базы DV Auth не раскрывает пароли.
- **Секреты хранятся осторожно.** Секреты TOTP зашифрованы (AES-256-GCM), запасные коды лежат
  только хешем, токен проверки личности в чате нигде не сохраняется.
- **Защита от перебора.** Пять неверных кодов сжигают талон входа, пять неудач за 15 минут
  блокируют попытки, повторное использование кода невозможно даже при двух одновременных запросах.
- **Защита от подмены.** Число с экрана и показ в приложении чата адреса и браузера, откуда
  входят, не дают подтвердить чужой вход случайно.
- **Никаких чужих сервисов.** Ни SMS, ни почты, ни облачных провайдеров второго фактора.
- **Проверен на настоящей базе.** Интеграционные тесты идут на настоящем PostgreSQL и на
  имитации Synapse, а не на заглушках внутренней логики.

## Как это работает

Участников три: ваше приложение, DV Auth и (для основного способа) чат на Matrix.

    браузер  ──пароль──▶  ваше приложение ──«этот человек входит»──▶  DV Auth
                              │                                          │
                              │◀──────── «нужен второй шаг, талон» ──────┘
                              │
    браузер  ◀── QR + число ──┘
    телефон: чат сканирует QR, человек вводит число ──▶ DV Auth ──▶ Synapse: «чей это токен?»
                              │
    браузер  ──опрос──▶  ваше приложение ──▶ DV Auth: «подтверждено?» ──▶ да: открыть сессию

Подробности: docs/ARCHITECTURE.md (как устроено), docs/API.md (все запросы), docs/INTEGRATION.md
(как подключить своё приложение), docs/CHAT.md (подтверждение в чате), docs/SECURITY.md (что и
от чего защищено).

## Быстрый старт

Нужны Node.js 22 или новее и PostgreSQL. Полная инструкция с Docker, systemd и прокси:
docs/DEPLOY.md.

    git clone https://github.com/Godween69/DVAuth.git
    cd DVAuth
    npm ci
    cp dvauth.env.example dvauth.env
    # заполните dvauth.env: база, приложения (DVAUTH_CLIENTS), ключ TOTP и/или адрес Synapse
    node --env-file=dvauth.env src/migrate-cli.js
    node --env-file=dvauth.env src/main.js

Проверка, что сервис жив:

    curl http://127.0.0.1:3011/health

## Как подключить своё приложение

Приложение после проверки пароля делает один запрос `POST /v1/login/begin`. Если у человека
второй фактор не включён, ответ `{"required": false}` и вход идёт как обычно. Если включён,
приходит талон и список способов, приложение показывает второй шаг, а потом открывает сессию.
Рабочий пример на TypeScript (NestJS) и пошаговая схема: docs/INTEGRATION.md.

## Тесты

    npm test                                   # быстрые тесты без базы
    DVAUTH_TEST_DATABASE_URL=postgres://postgres@127.0.0.1:5432/postgres npm run test:db

Интеграционные тесты сами создают и удаляют временную базу. Проверка лицензий зависимостей:
`npm run licenses`.

## Что в репозитории

- src/: код сервиса (карта в docs/ARCHITECTURE.md)
- migrations/: SQL-миграции базы
- test/: тесты
- docs/: документация
- Dockerfile, docker-compose.example.yml, dvauth.env.example: для развёртывания

В репозитории намеренно нет секретов и адресов чьей-либо инфраструктуры: всё это вы задаёте
сами в dvauth.env.
